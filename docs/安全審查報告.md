**審查日期**: 2026-04-18  
**審查範圍**: Backend (Django), Frontend (React), Dependencies, Infrastructure

## 📋 執行摘要

HeartBox 專案整體安全性配置良好，後端採用 Django REST Framework 並實作了完整的安全中間件和認證機制。前端使用 React 19 並正確處理 XSS 防護。主要發現 **2 個中等嚴重性依賴項漏洞**和 **1 個依賴版本不兼容問題**，建議盡快修復。

### 安全等級評估
- 🟢 **整體安全性**: 良好 (B+)
- 🟢 **後端安全**: 優秀 (A)
- 🟡 **前端安全**: 良好 (B+) - 需修復依賴漏洞
- 🟢 **認證授權**: 優秀 (A)
- 🟢 **密鑰管理**: 優秀 (A)
- 🟡 **依賴項安全**: 需要改進 (C+)

## 🔍 詳細發現

### 1. 後端安全性 (Django REST Framework)

#### ✅ 良好實踐

1. **密鑰管理**
   - ✅ `SECRET_KEY` 從環境變數載入，且有驗證機制
   - ✅ `ENCRYPTION_KEY` 使用 Fernet，有格式驗證（32 bytes base64）
   - ✅ `LLM_SERVER_URL` / `LLM_SERVER_API_KEY` 從環境變數載入（取代舊 `OPENAI_API_KEY`；Phase 0b 後已切自架 TAIDE/LLaVA，資料不離境）
   - ✅ `.env.example` 不包含實際密鑰值

2. **認證與授權**
   - ✅ JWT 配置完善：
     - ACCESS_TOKEN_LIFETIME: 30 分鐘（合理）
     - REFRESH_TOKEN_LIFETIME: 7 天（合理）
     - ROTATE_REFRESH_TOKENS: True（防止重放攻擊）
     - BLACKLIST_AFTER_ROTATION: True（防止舊 token 被重用）
   - ✅ 沒有發現未授權的 API 端點（無空 `permission_classes`）
   - ✅ 速率限制配置完善：
     - 用戶操作: 200/hour
     - 登入: 10/hour
     - 註冊: 5/hour
     - 密碼重設: 5/hour

3. **SQL Injection 防護**
   - ✅ 全部使用 Django ORM，未發現 `.raw()` 或 `.extra()` 原始 SQL 查詢
   - ✅ 所有查詢參數都經過 ORM 處理

4. **CSRF 防護**
   - ✅ `CsrfViewMiddleware` 已啟用
   - ✅ 生產環境使用 `CSRF_COOKIE_SECURE = True`
   - ✅ `CSRF_TRUSTED_ORIGINS` 從環境變數配置

5. **生產環境安全設定**
   ```python
   # settings.py (第 318-326 行)
   if not DEBUG:
       SECURE_SSL_REDIRECT = True                    # ✅ 強制 HTTPS
       SECURE_HSTS_SECONDS = 31536000                # ✅ HSTS 1 年
       SECURE_HSTS_INCLUDE_SUBDOMAINS = True         # ✅ 包含子域名
       SECURE_HSTS_PRELOAD = True                    # ✅ 支援 HSTS preload
       SESSION_COOKIE_SECURE = True                  # ✅ Session cookie 僅 HTTPS
       CSRF_COOKIE_SECURE = True                     # ✅ CSRF cookie 僅 HTTPS
       SECURE_CONTENT_TYPE_NOSNIFF = True            # ✅ 防止 MIME 類型嗅探
       SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https')  # ✅ 反向代理支援
   ```

6. **安全標頭 (Security Headers)**
   - ✅ `ContentSecurityPolicyMiddleware` 實作完整（`api/middleware.py`）
   - ✅ `Referrer-Policy: strict-origin-when-cross-origin`
   - ✅ `Permissions-Policy: camera=(), microphone=(), geolocation=()`
   - ✅ `X-Frame-Options` 透過 `XFrameOptionsMiddleware`

7. **CORS 配置**
   ```python
   # settings.py (第 159-167 行)
   if DEBUG:
       CORS_ALLOWED_ORIGINS = [f'http://localhost:{p}' for p in range(5173, 5180)]
       CSRF_TRUSTED_ORIGINS = [f'http://localhost:{p}' for p in range(5173, 5180)]
   else:
       CORS_ALLOWED_ORIGINS = os.getenv('CORS_ALLOWED_ORIGINS', '').split(',')
       CSRF_TRUSTED_ORIGINS = os.getenv('CSRF_TRUSTED_ORIGINS', '').split(',')
   ```
   - ✅ 開發與生產環境分離配置
   - ✅ 生產環境需從環境變數明確指定允許的來源

8. **錯誤追蹤與監控**
   - ✅ Sentry 配置正確（`send_default_pii=False` 不發送個人識別資訊）

#### ⚠️ 需要注意的項目

1. **Content Security Policy**
   ```python
   # settings.py (第 329-335 行)
   CSP_STYLE_SRC = ("'self'", "'unsafe-inline'")  # ⚠️ 允許 inline styles
   ```
   - **風險等級**: 低
   - **說明**: `'unsafe-inline'` 允許內聯樣式，可能增加 XSS 風險
   - **建議**: 
     - 如果使用 Tailwind CSS 或 CSS-in-JS，這是必要的
     - 考慮使用 nonce 或 hash-based CSP 提升安全性
     - 監控是否有實際的內聯樣式注入風險

2. **WebSocket Token 認證**
   ```python
   # api/middleware.py (第 34-37 行)
   if token_list:
       scope['user'] = await get_user_from_token(token_list[0])
   ```
   - **風險等級**: 低
   - **說明**: WebSocket 支援 query string token 認證（`?token=<JWT>`）
   - **潛在問題**: Token 可能出現在伺服器日誌、瀏覽器歷史記錄中
   - **緩解措施**: 
     - ✅ 已實作優先級更高的 first-message auth（推薦方式）
     - ✅ Query string 僅作為向後兼容的備用方案
   - **建議**: 在文檔中明確建議客戶端使用 message-based auth

### 2. 前端安全性 (React + Vite)

#### ✅ 良好實踐

1. **XSS 防護**
   - ✅ 所有 `dangerouslySetInnerHTML` 使用都有 `DOMPurify.sanitize`
   - ✅ 發現 4 處使用，全部安全：
     ```javascript
     // LessonPage.jsx:119
     dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(mdToHtml(content)) }}
     
     // NoteDetailPage.jsx:223
     dangerouslySetInnerHTML={{ __html: sanitizedContent }}
     
     // PsychoContentPage.jsx:193
     dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(mdToHtml(content)) }}
     
     // LandingPage.jsx:20 (結構化數據，JSON.stringify)
     dangerouslySetInnerHTML={{ __html: JSON.stringify({...}) }}
     ```

2. **localStorage 使用**
   - ✅ 所有 localStorage 使用都是非敏感資料：
     - `theme`: 主題偏好
     - `language`: 語言偏好
     - `heartbox_user_cache`: 用戶快取（僅基本資訊，不含密碼）
     - `heartbox_draft`: 筆記草稿
     - `heartbox_search_history`: 搜尋歷史
     - `heartbox_font_scale`: 字體大小
     - `heartbox_idle_timeout`: 空閒超時設定
   - ✅ JWT tokens 儲存在獨立的 `tokenStorage` 中（未與其他資料混合）

3. **認證 Token 管理**
   - ✅ Access token 和 refresh token 分離儲存
   - ✅ Logout 時清除所有快取（localStorage + Cache API）
   - ✅ Token 過期後自動清除並重定向到登入頁

#### ⚠️ 需要改進的項目

1. **調試日誌 (console.log)**
   - **位置**: `frontend/src/services/healthKit.js`
   - **行數**: 25, 29, 37-38, 76
   - **風險等級**: 低
   - **建議**: 
     - 生產環境移除或使用環境變數控制
     - 使用 Vite 的 `import.meta.env.DEV` 條件式輸出
     ```javascript
     if (import.meta.env.DEV) {
       console.log('[HealthKit] Platform detected:', platform)
     }
     ```

2. **DOMPurify 版本過舊**
   - **當前版本**: 3.3.1
   - **漏洞**: CVE-2025-XXXX (GHSA-39q2-94rc-95cp)
   - **嚴重性**: 中等 (Moderate)
   - **影響**: `ADD_TAGS` 功能可能繞過 `FORBID_TAGS` 限制
   - **修復**: 升級到 `dompurify@^3.3.4` 或更高版本
   ```bash
   npm update dompurify
   ```

### 3. 依賴項安全性

#### ❌ 需要修復的漏洞

1. **frontend/package.json**

   **漏洞 #1: DOMPurify**
   - **套件**: `dompurify@3.3.1`
   - **漏洞 ID**: GHSA-39q2-94rc-95cp
   - **嚴重性**: Moderate
   - **CVE**: CWE-783
   - **影響範圍**: `dompurify@<=3.3.3`
   - **修復方式**:
     ```bash
     cd frontend
     npm update dompurify
     ```
   - **預期版本**: `dompurify@>=3.3.4`

   **漏洞 #2: follow-redirects**
   - **套件**: `follow-redirects` (axios 的依賴)
   - **漏洞 ID**: GHSA-r4q5-vmmm-2653
   - **嚴重性**: Moderate
   - **CVE**: CWE-200 (資訊洩露)
   - **影響**: 洩漏自定義認證標頭到跨域重定向目標
   - **修復方式**:
     ```bash
     cd frontend
     npm update axios
     # 或強制更新 follow-redirects
     npm update follow-redirects
     ```

   **總計**: 2 個中等嚴重性漏洞

2. **backend/requirements.txt**

   **依賴版本不兼容**:
   - **問題**: `pyopenssl 25.1.0` 需要 `cryptography<46`，但安裝了 `cryptography@46.0.5`
   - **影響**: 可能導致 TLS/SSL 功能異常
   - **修復方式**:
     ```bash
     cd backend
     # 選項 1: 降級 cryptography
     venv/Scripts/python.exe -m pip install "cryptography<46"
     
     # 選項 2: 升級 pyopenssl (推薦)
     venv/Scripts/python.exe -m pip install --upgrade pyopenssl
     
     # 選項 3: 移除 pyopenssl（如果不需要）
     venv/Scripts/python.exe -m pip uninstall pyopenssl
     ```

   **建議**: 運行 `pip check` 並解決所有依賴衝突
