# HeartBox 資料庫備份策略指南

## 概述

資料庫是 HeartBox 最關鍵的資產，包含所有用戶的加密筆記、健康資料和個人資訊。完善的備份策略可以確保：
- 防止資料永久遺失
- 災難恢復能力
- 符合資料保護法規要求

## 目前使用的資料庫

根據專案配置，HeartBox 目前使用：
- **開發環境：** SQLite (local file)
- **生產環境：** PostgreSQL (Neon 或 GCP Cloud SQL)

## 備份策略設計

### 1. 備份頻率

**建議配置：**
- **每日自動備份：** 凌晨 2:00 AM (Asia/Taipei)
- **保留期限：** 7 天（最近 7 個每日備份）
- **每週備份：** 每週日額外保留一份（保留 4 週）
- **每月備份：** 每月 1 日額外保留一份（保留 12 個月）

### 2. 備份類型

#### 全量備份 (Full Backup)
- 備份整個資料庫的完整副本
- 建議頻率：每日
- 優點：恢復簡單快速
- 缺點：佔用較多儲存空間

#### 增量備份 (Incremental Backup)
- 只備份自上次備份以來的變更
- 建議頻率：每小時（可選，針對高流量時期）
- 優點：節省儲存空間和備份時間
- 缺點：恢復較複雜

### 3. 備份儲存位置

**主要備份：** GCP Cloud SQL 自動備份
**異地備份：** Google Cloud Storage (不同地區)

## GCP Cloud SQL 自動備份設定

### 前提條件

1. 已創建 GCP Cloud SQL PostgreSQL 實例
2. 已安裝並配置 `gcloud` CLI
3. 具有適當的 GCP 權限（roles/cloudsql.admin）

### 方法一：使用 GCP Console（圖形介面）

1. **登入 GCP Console**
   - 前往 [cloud.google.com/console](https://console.cloud.google.com)
   - 選擇專案：`heartbox-app`

2. **導航至 Cloud SQL**
   - 左側選單 → SQL → 選擇您的實例

3. **編輯備份設定**
   - 點擊實例名稱
   - 進入「Backups」分頁
   - 點擊「EDIT BACKUP CONFIGURATION」

4. **配置自動備份**
   ```
   Automated backups: Enabled
   Backup window: 
     - Start time: 02:00 - 06:00 (Asia/Taipei)
     - Allow to run any time: No
   
   Backup retention: 7 days
   
   Point-in-time recovery (PITR): Enabled
     - Transaction log retention: 7 days
     - This allows recovery to any point within the last 7 days
   
   Backup location: asia-east1 (Taiwan)
   ```

5. **儲存設定**

### 方法二：使用 gcloud CLI（命令列）

```bash
# 1. 設定預設專案
gcloud config set project heartbox-app

# 2. 列出現有的 Cloud SQL 實例
gcloud sql instances list

# 3. 更新備份配置
gcloud sql instances patch YOUR_INSTANCE_NAME \
  --backup-start-time=02:00 \
  --retained-backups-count=7 \
  --retained-transaction-log-days=7 \
  --enable-point-in-time-recovery \
  --backup-location=asia-east1

# 4. 驗證備份設定
gcloud sql instances describe YOUR_INSTANCE_NAME \
  --format="yaml(settings.backupConfiguration)"
```

**參數說明：**
- `--backup-start-time=02:00`：每日 2:00 AM 開始備份
- `--retained-backups-count=7`：保留最近 7 個備份
- `--retained-transaction-log-days=7`：保留 7 天的交易日誌（PITR）
- `--enable-point-in-time-recovery`：啟用時間點恢復
- `--backup-location=asia-east1`：備份儲存在台灣區域

### 方法三：使用 Terraform（基礎設施即程式碼）

創建 `terraform/cloudsql_backup.tf`：

```hcl
resource "google_sql_database_instance" "heartbox_db" {
  name             = "heartbox-db"
  database_version = "POSTGRES_15"
  region           = "asia-east1"

  settings {
    tier = "db-f1-micro"  # 根據需求調整

    backup_configuration {
      enabled                        = true
      start_time                     = "02:00"
      point_in_time_recovery_enabled = true
      transaction_log_retention_days = 7
      backup_retention_settings {
        retained_backups = 7
        retention_unit   = "COUNT"
      }
      location = "asia-east1"
    }

    # 高可用性配置（可選，成本較高）
    availability_type = "REGIONAL"  # 或 "ZONAL"
  }

  deletion_protection = true
}
```

應用配置：
```bash
terraform init
terraform plan
terraform apply
```

## Neon PostgreSQL 備份設定

如果使用 Neon (serverless PostgreSQL)：

### Neon 自動備份

Neon 預設提供：
- **自動備份：** 每日自動備份
- **保留期限：** 
  - Free plan: 7 天
  - Pro plan: 30 天
- **時間點恢復（PITR）：** 可恢復到任意時間點（保留期限內）

### 啟用 Neon 備份

1. **登入 Neon Console**
   - 前往 [console.neon.tech](https://console.neon.tech)

2. **選擇專案**
   - 選擇 HeartBox 專案

3. **配置備份**
   - Settings → Backups
   - Automated backups: Enabled（預設已啟用）
   - Point-in-time recovery: Enabled

4. **設定保留期限**
   - Free plan: 最多 7 天
   - Pro plan: 最多 30 天

### 手動備份（Neon）

Neon 支援分支（Branch）功能，可用於快照備份：

```bash
# 使用 Neon CLI 創建分支（快照）
neonctl branches create --name manual-backup-$(date +%Y%m%d)
```

## 手動備份程序

### 使用 pg_dump（適用於所有 PostgreSQL）

#### 1. 本地備份腳本

創建 `backend/scripts/backup_db.sh`：

```bash
#!/bin/bash

# HeartBox Database Backup Script

# 設定
BACKUP_DIR="$HOME/heartbox-backups"
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_FILE="$BACKUP_DIR/heartbox_backup_$DATE.sql"
DB_URL="$DATABASE_URL"  # 從環境變數讀取

# 確保備份目錄存在
mkdir -p "$BACKUP_DIR"

# 執行備份
echo "Starting backup at $(date)"
pg_dump "$DB_URL" -F c -b -v -f "$BACKUP_FILE"

# 壓縮備份檔案
gzip "$BACKUP_FILE"

# 刪除 7 天前的備份
find "$BACKUP_DIR" -name "*.sql.gz" -mtime +7 -delete

echo "Backup completed: $BACKUP_FILE.gz"
```

#### 2. 設定執行權限

```bash
chmod +x backend/scripts/backup_db.sh
```

#### 3. 執行備份

```bash
export DATABASE_URL="postgresql://user:password@host:5432/database"
./backend/scripts/backup_db.sh
```

### 使用 Django Management Command

創建 `backend/api/management/commands/backup_db.py`：

```python
from django.core.management.base import BaseCommand
from django.core.management import call_command
from django.conf import settings
import subprocess
from datetime import datetime
import os

class Command(BaseCommand):
    help = 'Backup database to file'

    def add_arguments(self, parser):
        parser.add_argument(
            '--output-dir',
            type=str,
            default='./backups',
            help='Output directory for backup files',
        )

    def handle(self, *args, **options):
        output_dir = options['output_dir']
        os.makedirs(output_dir, exist_ok=True)

        timestamp = datetime.now().strftime('%Y%m%d_%H%M%S')
        output_file = os.path.join(output_dir, f'heartbox_backup_{timestamp}.json')

        self.stdout.write('Starting database backup...')

        # 使用 Django's dumpdata 命令
        with open(output_file, 'w', encoding='utf-8') as f:
            call_command('dumpdata', '--natural-foreign', '--natural-primary', stdout=f)

        # 壓縮
        subprocess.run(['gzip', output_file])

        self.stdout.write(self.style.SUCCESS(
            f'Backup completed: {output_file}.gz'
        ))
```

執行：
```bash
python manage.py backup_db --output-dir=/path/to/backups
```

## 異地備份（Offsite Backup）

### 使用 Google Cloud Storage

#### 1. 創建 GCS Bucket

```bash
# 創建備份用的 bucket（不同區域以防災）
gsutil mb -p heartbox-app -c STANDARD -l us-central1 gs://heartbox-backups-us

# 設定生命週期規則（自動刪除 30 天前的備份）
cat > lifecycle.json <<EOF
{
  "lifecycle": {
    "rule": [
      {
        "action": {"type": "Delete"},
        "condition": {"age": 30}
      }
    ]
  }
}
EOF

gsutil lifecycle set lifecycle.json gs://heartbox-backups-us
```

#### 2. 自動上傳備份至 GCS

擴展備份腳本：

```bash
#!/bin/bash

# ... (前面的備份程式碼)

# 上傳至 GCS
echo "Uploading to Google Cloud Storage..."
gsutil cp "$BACKUP_FILE.gz" gs://heartbox-backups-us/daily/

echo "Backup uploaded to GCS"
```

#### 3. 使用 Cloud Storage Transfer

設定自動從 Cloud SQL 備份至 Cloud Storage：

```bash
# 匯出 Cloud SQL 備份至 GCS
gcloud sql export sql YOUR_INSTANCE_NAME \
  gs://heartbox-backups-us/cloudsql/backup_$(date +%Y%m%d).sql \
  --database=heartbox
```

## 備份恢復程序

### 從 GCP Cloud SQL 備份恢復

#### 方法一：使用 GCP Console

1. 前往 Cloud SQL → 選擇實例
2. 點擊「Backups」分頁
3. 選擇要恢復的備份
4. 點擊「Restore」
5. 選擇恢復方式：
   - **恢復到現有實例**（會覆蓋現有資料）
   - **恢復到新實例**（建議，較安全）

#### 方法二：使用 gcloud CLI

```bash
# 列出可用的備份
gcloud sql backups list --instance=YOUR_INSTANCE_NAME

# 恢復到現有實例
gcloud sql backups restore BACKUP_ID \
  --backup-instance=YOUR_INSTANCE_NAME \
  --backup-id=BACKUP_ID

# 或創建新實例並恢復
gcloud sql instances create heartbox-db-restored \
  --source-instance=YOUR_INSTANCE_NAME \
  --source-backup=BACKUP_ID
```

### 從 pg_dump 檔案恢復

```bash
# 解壓縮備份檔案
gunzip heartbox_backup_20260412.sql.gz

# 恢復資料庫
pg_restore -d heartbox_db heartbox_backup_20260412.sql

# 或使用 psql (for plain SQL format)
psql heartbox_db < heartbox_backup_20260412.sql
```

### 時間點恢復（Point-in-Time Recovery, PITR）

恢復到特定時間點（需啟用 PITR）：

```bash
gcloud sql backups restore BACKUP_ID \
  --backup-instance=YOUR_INSTANCE_NAME \
  --point-in-time=2026-04-12T03:00:00Z
```

## 備份測試

定期測試備份恢復流程非常重要！

### 測試計劃

**每季度執行：**
1. 選擇一個備份檔案
2. 恢復到測試環境/新實例
3. 驗證資料完整性：
   - 記錄數量正確
   - 最近的資料存在
   - 加密資料可正確解密
4. 記錄恢復所需時間
5. 文件化任何問題

### 測試腳本

```bash
#!/bin/bash
# 備份恢復測試腳本

echo "=== Backup Recovery Test ==="
echo "Date: $(date)"

# 1. 創建測試實例
gcloud sql instances create test-restore-instance \
  --source-instance=heartbox-db \
  --source-backup=LATEST_BACKUP_ID

# 2. 等待實例就緒
echo "Waiting for instance to be ready..."
gcloud sql operations wait ...

# 3. 連線測試
echo "Testing database connection..."
psql "host=<ip> user=postgres dbname=heartbox" -c "SELECT COUNT(*) FROM api_moodnote;"

# 4. 測試完成後刪除測試實例
read -p "Test completed. Delete test instance? (y/n) " -n 1 -r
if [[ $REPLY =~ ^[Yy]$ ]]; then
    gcloud sql instances delete test-restore-instance --quiet
fi
```

### 備份狀態檢查腳本

創建 `backend/scripts/check_backup_status.py`：

```python
from google.cloud import sql_v1
from datetime import datetime, timedelta
import sys

def check_recent_backup(instance_name, project_id):
    client = sql_v1.SqlBackupRunsServiceClient()
    
    # 列出最近的備份
    request = sql_v1.SqlBackupRunsListRequest(
        project=project_id,
        instance=instance_name,
    )
    
    backups = client.list(request=request)
    
    # 檢查最近 24 小時內是否有成功的備份
    now = datetime.utcnow()
    found_recent = False
    
    for backup in backups:
        if backup.status == 'SUCCESSFUL':
            backup_time = backup.window_start_time
            if (now - backup_time) < timedelta(hours=24):
                print(f"✓ Recent backup found: {backup_time}")
                found_recent = True
                break
    
    if not found_recent:
        print("✗ No successful backup in the last 24 hours!")
        sys.exit(1)
    
    return found_recent

if __name__ == '__main__':
    check_recent_backup('heartbox-db', 'heartbox-app')
```

## 安全性考量

### 備份加密

1. **傳輸加密：** GCP Cloud SQL 備份預設使用 TLS 加密傳輸
2. **儲存加密：** 備份在儲存時自動使用 Google-managed encryption keys 加密
3. **額外加密：** 可使用 Customer-managed encryption keys (CMEK)

### 存取控制

```bash
# 設定 IAM 權限（最小權限原則）
gcloud projects add-iam-policy-binding heartbox-app \
  --member=serviceAccount:backup-service@heartbox-app.iam.gserviceaccount.com \
  --role=roles/cloudsql.viewer

# 備份檔案權限
gsutil iam ch \
  serviceAccount:backup-service@heartbox-app.iam.gserviceaccount.com:objectViewer \
  gs://heartbox-backups-us
```

### 合規性

確保備份策略符合：
- **GDPR：** 用戶刪除帳號後，備份中的資料也應在合理時間內刪除
- **台灣個資法：** 備份資料應妥善保護，防止外洩
