# 專題簡介

**HeartBox 心事盒** — 結合 AI 情緒分析 + 長期心情統計 + 個人化建議的心理日記網站，網頁版加 iOS App。

**最大特色**：
- 自架繁中 LLM（TAIDE）做情緒分析，日記內容從不離開我們的伺服器
- 用 lm-format-enforcer 強制 LLM 輸出 JSON，100% 可靠
- 結合天氣 + 長期心情規律給個人化建議
- 資料庫 Fernet AES-128 欄位加密

# 設計要求

- **風格**：跟主圖一致 — 簡單、乾淨、適合 PPT

# 我要的 12 張子流程詳細圖

## 圖 A：官網首頁 (LandingPage)

**入口**：訪客打開 `heartbox.tw`

**頁面有什麼**：
- Hero 區：Logo + 「HeartBox 心事盒」標題 + 副標「AI 陪你看見心情的規律」+ 兩個 CTA 按鈕
- 5 張功能特色卡片：智慧日記 / AI 對話 / 個人化洞察 / 呼吸練習 / 自我評估
- Footer：關於 / 條款 / 隱私 / FAQ

**使用者流程**：
1. 訪客打開首頁
2. 看 Hero 區理解產品
3. 滾下去看功能特色
4. 決定要不要註冊：
   - 已有帳號 → 點「登入」
   - 沒有 → 點「免費註冊」

**樣式建議**：用 `flowchart TD`，3 個分支結尾（登入頁 / 註冊頁 / 離開）。

## 圖 B：註冊流程（含 Email 驗證 + 13-17 家長同意）

**入口**：從 LandingPage 點「免費註冊」

**步驟**：
1. 填表單：username / email / password / 確認密碼
2. 選年齡帶：18+ / 13-17 / under 13
3. 勾 4 個同意：服務條款 / 隱私政策 / 13 歲以上聲明 /（選）AI 訓練同意
4. 系統判斷年齡：
   - under 13 → 拒絕註冊（法律不允許）
   - 13-17 → 加家長 email → 寄信給家長 → 等家長點同意連結 → 解鎖
   - 18+ → 直接進下一步
5. 系統檢查 username/email 唯一性
6. 系統建立 User + 寄驗證信
7. 使用者收信點驗證連結 → email_verified=True
8. 自動跳登入頁

**重點**：強調「未滿 13 歲拒絕」「13-17 家長同意」是法規合規

## 圖 C：登入流程（含 2FA + Cold Start 處理）

**入口**：從 LandingPage 點「登入」或 Token 過期被推回 /login

**步驟**：
1. 系統暖機 ping（背景打 /healthz/，避免 Cloud Run 冷啟動）
2. 使用者填 username + password
3. （選）勾「記住我」
4. 按「登入」
5. 系統判斷帳號狀態：
   - 被鎖定（5 次錯誤 → 鎖 15 分）→ 顯示「帳號暫時鎖定」
   - 帳密錯 → failed_login_count++ + 顯示錯誤
   - 帳密對 → 繼續
6. 系統判斷是否啟用 2FA：
   - 啟用 → 跳 2FA 表單 → 使用者輸入 Google Authenticator 6 位數 → 驗證
   - 沒啟用 → 直接發 JWT
7. 拿到 JWT → 進日誌主頁

**3 秒後顯示「正在喚醒伺服器」進度條**（Cloud Run 冷啟可達 30 秒）

## 圖 F：AI 情緒分析詳細流程（核心循環的「AI 情緒分析」box）

**入口**：使用者按下儲存後，後端背景觸發

**步驟（sequence diagram 適合）**：
1. 後端開新 Thread 跑 `ai_engine.analyze(content)`
2. Tier 1：呼叫 TAIDE-LX-7B + lm-format-enforcer 強制 JSON 輸出
3. TAIDE 回傳 `{sentiment_score: float, stress_index: int}` (100% JSON)
4. 後端產生 ai_feedback（呼叫 TAIDE 第二次生成自然語言回饋）
5. 系統判斷內容是否含危機字眼：
   - 有 → 觸發 CrisisGuard，加 1995 熱線
   - 無 → 一般 feedback
6. 系統更新 MoodNote（加密 ai_feedback）
7. 透過 WebSocket 推送 'heartbox:note_analyzed' event
8. 前端收到事件 → 自動更新該篇日記顯示情緒分數 + AI 回饋（不用重整）

**Fallback 4 層**：
- TAIDE 給 JSON → 用真實分析（**100%**，因為 lm-format-enforcer 強制）
- TAIDE 連線失敗 → 本地詞典分析（Tier 2）
- 詞典也失敗 → 預設模板（Tier 3）
- 任何情況下危機字眼都會啟動 CrisisGuard

**重點**：用 sequence diagram，強調「非同步 + 4 層 fallback」

## 圖 G：今日個人化建議詳細流程（核心循環的「今日建議」box）

**入口**：使用者打開日誌主頁時，widget 自動載入

**步驟**：
1. 前端取得地理位置（瀏覽器定位 / Taipei fallback）
2. POST `/api/personal-suggestion/` with {lat, lon}
3. 後端檢查 cache（每人每天每地區 12h cache）
4. Cache miss → 並行收集：
   - 使用者長期心情規律（從 DB 算 5 維度個人化洞察）
   - 今天天氣（Open-Meteo API）
   - 今天日期屬性（平日/週末/月段）
5. 計算今天命中哪些觸發條件
6. 組合 prompt 給 TAIDE
7. TAIDE 寫 2-3 句暖心建議
8. 後端 cache 12 小時
9. 前端顯示 widget：天氣行 + 暖心建議

**Fallback**：TAIDE 失敗 → 顯示固定模板 tips（10 條預寫的）

## 圖 H：分析 / 心情週報詳細流程

**入口**：頂部導覽列點「分析」→「心情週報/月報」

**頁面區塊**：
1. **即時資訊**（4 個 metric cards）：連續記錄 / 本週平均 / 本月日記數 / 感恩紀錄數
2. **趨勢圖表**：心情趨勢折線圖 / 心情×溫度散布圖 / 標籤頻次
3. **歷史回顧**：個人化洞察 5 維度（月段 / 平日週末 / 月份 / 天氣 / 溫度）
4. **行事曆 + 年度像素圖**

**使用者操作**：
1. 打開頁面 → 自動載入 180 天資料
2. 看趨勢圖找規律
3. 看 PersonalInsights 卡片（系統自動找出規律）
4. （選）切換 lookback：30/90/180/365 天
5. （選）點行事曆某天 → 跳該日的日記列表

**重點**：說明「不靠 LLM」純統計算規律（5 維度 + 樣本門檻）

## 圖 I：問卷評估流程（含分享給諮商師）

**入口**：頂部導覽列「分析」→「問卷評估」

**步驟**：
1. 看到量表列表：PHQ-9（憂鬱）/ GAD-7（焦慮）/ PSS-10（壓力）/ ISI（失眠）
2. 選一個 → 開始填寫
3. 逐題回答（1-5 量尺）
4. 送出
5. 系統算總分 + 解讀（輕度 / 中度 / 重度）
6. 系統判斷：分數高於警示閾值？
   - 是 → 自動觸發 alert，顯示 CrisisBanner
   - 否 → 一般顯示
7. 顯示結果頁：分數 + 解讀 + 建議
8. （選）「分享給諮商師」按鈕 → 選諮商師 → 送出

**重點**：強調量表是國際標準 + 自動觸發危機警示

## 圖 J：社群 / 匿名社群詳細流程

**入口**：頂部導覽列「社群」→「匿名社群」

**頁面區塊**：
1. 類別 filter chips（紓壓 / 情感 / 工作 / 生活 / 全部）
2. 「+ 發新貼文」按鈕（右下角 FAB）
3. 貼文 grid（PostCard）

**使用者操作**：
1. 瀏覽貼文 → 按類別篩選
2. （選）點貼文進詳情頁 → 看內容 + 留言串
3. （選）按 ❤ 按讚
4. （選）寫留言
5. （選）「⋯ 檢舉」→ 選原因（垃圾 / 騷擾 / 自傷 / 違法）→ 進管理員審核 queue
6. （選）「+ 發新貼文」→ 寫內容 + 選類別 + 勾匿名（預設）→ 送出
7. 系統做關鍵字偵測，含危機字眼 → 跳 CrisisBanner（仍允許發文）

**重點**：匿名保護 + 危機字眼處理 + 檢舉機制

## 圖 K：AI 聊天 (RAG) 詳細流程

**入口**：頂部導覽列「社群」→「AI 聊天」

**步驟**：
1. 進入頁面 → 看到 Session 列表 + 「+ 新對話」
2. 開新對話 OR 點舊 session
3. 使用者輸入訊息 → 送出
4. 系統儲存 user message（加密）
5. 抓最近 N 輪對話作為 context
6. RAG：用 bge-m3 把 user message 轉向量
7. RAG：從 ChromaDB 找最相關的 3-5 篇心理知識文章
8. 組合：對話歷史 + 檢索文章 → 給 TAIDE
9. TAIDE 推理 5-15 秒
10. 系統 sanitize 輸出
11. 系統判斷危機字眼
12. 儲存 + 顯示給使用者
13. （選）使用者對 AI 訊息按 👍 / 👎 評分

**重點**：強調 RAG 結合「心理知識庫」+ TAIDE 寫自然語言

## 圖 L：CrisisBanner 安全防護橫向流程

**這是一個橫跨多個頁面的安全機制，不屬於單一頁面**

**觸發點**：4 種寫入動作之後
- 日記內容
- AI 對話訊息
- 社群貼文
- 自我評估結果（高分）

**流程**：
1. 使用者寫內容並送出
2. 後端關鍵字偵測（詞典 + LLM 雙保險）
3. 偵測「自殺 / 自殘 / 想死 / 結束生命」等詞
4. 判斷是否命中：
   - 否 → 正常流程繼續
   - 是 → 後端 response 加 `crisis_detected: true` + hotlines
5. 前端 axios interceptor 攔截 response → 觸發全域 CrisisBanner
6. 整個畫面跳出 banner：
   - 「你並不孤單，這裡可以求助」
   - 1995 生命線 / 113 婦幼專線 / 112 緊急電話
   - 「我已經沒事了」按鈕可關閉
7. 後端寫 AuditLog 追蹤

**樣式**：用紅色 / 警示色標示「危機字眼觸發」分支
